# NS-30 — Guided date, time and numeric capture inputs

Ticket: [NS-30](https://digirati.atlassian.net/browse/NS-30).

## Implemented behavior

The existing Text field now offers a grouped format selector with explicit templates and examples. Presets cover whole numbers, decimal point/comma numbers, day-first/month-first/year-first dates, month/year and year-only values, 24-hour times with optional seconds, and common date-and-time combinations. A local Try it input resets when the selected configuration changes so each format can be tested immediately.

Fixed templates show the remaining pattern inside the input and insert separators as contributors type. Calendar and clock feedback appears on completion or blur; unfinished focused input is not marked red. Numeric values remain strings, preserving leading zeros and precision. Paste must match the selected shape rather than silently discarding content or changing date order.

Custom patterns use `#` for digits, `@` for letters and `*` for letters or digits, with escaping for literal symbols. Patterns are limited to 48 characters and 1–32 input slots. They validate shape only. The outer settings Formik validates custom configuration for both explicit Save and unmount autosave. Preview values do not invalidate settings Save, and incomplete new examples cannot be adopted as defaults.

The default Text field creation bug is also fixed: the displayed and submitted field types agree, including when a plugin registers fields while the form is open. This fix is committed as `d262a9c0`.

## Compatibility and boundaries

Existing stored values and defaults are not rewritten on load or configuration changes. Legacy format IDs retain their accepted values; incompatible saved strings remain visible and editable. Guided date formats accept three-digit historical years without padding. The standalone Date field and its date representation are unchanged. Multiline fields retain unrestricted text entry and autosizing; unknown format IDs fall back to free text.

No database migration, timezone conversion, numeric coercion or dependency change is required. This is guided entry and input-level feedback, not enforcement across contribution submission, direct correction, approval or APIs. The separate tabular editor does not consume these Text field settings. The broader work is documented in [submission validation](NS-30-submission-validation.md).

## Delivery and verification

The [implementation plan](NS-30-guided-input-plan.md) records the design and boundaries. Commit `25ad5527` passed 114 tests across six focused suites and three independent review rounds. Tests cover pure masks/calendar logic, real input event handling, selection, paste, deletion, composition, literal translation labels, settings Save/unmount autosave, old defaults and preview isolation. Final build/browser results and limits are recorded in [integration verification](verification.md).

Browser checks on project 21 verified default field creation, persisted date/custom settings, automatic separators, partial/completed validation, corrected format labels, Try-it resets, historical replacements, Unicode deletion, custom correction paste and rejection of invalid settings during navigation. Temporary fields were removed without changing the existing fields. Real mobile IME ordering and native undo history remain unverified; screenshot capture was unavailable, so visual checks relied on the live DOM and computed layout.
