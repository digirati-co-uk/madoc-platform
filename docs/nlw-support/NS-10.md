# NS-10 — Editable transcription help text

## Current state and evidence

The ticket snapshot is `/tmp/madoc-nlw-NS-10.json`. Its historical comments are not evidence of current behavior. `services/madoc-ts/src/extensions/projects/templates/crowdsourced-transcription.ts` sets field label/description and structure/document instructions only during creation. Both structure and document editing are deliberately disabled. `project-model-editor.tsx` already supports a template-specific admin editor. `ApiClient.updateProjectTemplateConfig` and the site-admin-scoped `routes/projects/update-project-template-config.ts` already persist project JSON configuration. No migration is needed.

## Implementation plan

1. Add a transcription metadata helper under `src/extensions/projects/` to read optional existing template configuration, fall back to model metadata, and overlay changed help text without changing IDs, values, revisions or the source model.
2. Register a focused admin settings editor in `templates/crowdsourced-transcription.ts`. Save label, description and instructions through the existing template-config API, retaining unrelated configuration and explicit empty strings. Use existing Tailwind form conventions, loading/error states, Save and Cancel.
3. Register a transcription contributor editor that wraps `CanvasSimpleEditor` with a display transformation. Add an optional model transform prop to that existing component. Existing contributions receive updated help after reload; persistence is untouched.
4. Add focused regression tests for clearing, legacy fallbacks, immutability and contribution preservation.

## Acceptance tests

An existing plaintext transcription project exposes label, description and instructions on its Model page. Saving and reloading updates these on existing and newly started canvas contributions. Clearing description/instructions stays cleared rather than falling back to the original text. Cancel discards a draft. Existing model/field/revision IDs, transcription values, selectors, review strategy and unrelated template config remain unchanged. Failed saves retain the draft and show an error.

## Risks, boundaries and decisions

This is sensitive model-adjacent work: use a display overlay, never save or rebuild a capture model. The current PUT API replaces the template-config JSON, so concurrent administration has the same last-save-wins behavior as other users of that API; merge the loaded config locally. Open contributor sessions need reload to receive new project configuration. Review/admin preview rendering beyond this settings form is deferred: it may still show the historic model metadata. OCR correction and arbitrary custom templates are separate templates and are outside this ticket's bounded plaintext implementation. No new backend route, migration, review-policy change or design overhaul.
