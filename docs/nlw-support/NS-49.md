# NS-49 — correct approved contributions

Bounded implementation in the shared checkout, 2026-10-22. Ticket: <https://digirati.atlassian.net/browse/NS-49>. Source paths below are relative to `services/madoc-ts`. Parent owns builds and runtime checks.

## Delivered scope

`src/frontend/site/pages/tasks/review-listing/single-review.tsx` offers a separate “Correct values” action on completed, accepted ordinary contributions. Approve/reject/request-changes stay closed. Completed work can be viewed/corrected without its old review task; a missing review is tolerated only on completed work, while other API failures remain visible. Pending-review correction retains its existing editor and DirectEditButton behavior.

`correction-policy.ts` implements the chosen admin-only policy: `site.admin` OR (`models.admin` AND `models.create`), plus task status 3, a loaded accepted/approved revision, and no merge. This matches `src/utility/user-with-scope.ts`: `site.admin` bypasses requested-scope checks; `models.admin` alone does **not** grant whole-model PUT. The live admin token contains exactly `site.admin`, `tasks.admin`, `models.admin`, and is eligible. Limited reviewers and contributors gain no approved-correction permission. The same helper is checked again before save.

`ApprovedValueCorrection.tsx` embeds a bounded form inside the ordinary review view. It exposes existing synchronous built-in text, dropdown, checkbox/list, date and colour values, and numeric coordinates for existing box regions. Unsupported/rich/custom field types remain read-only; null/other selector states cannot be created or changed here. It provides explicit Save corrections and Cancel/discard confirmation, saving/error/success feedback, and no autosave. Shared canonical/inherited values may affect other contributions; the form states that limitation.

The form never exposes add/delete/reorder/merge/reassignment or schema controls. Tabular/custom review renderers and revisions carrying alignment snapshots are excluded. No full resource-model page is added. `DirectEditButton.tsx`, custom renderer contracts, backend policy and global ApiClient remain unchanged.

## Safe read and save contract

`save-value-corrections.ts` is the single correction helper. Entry and save load fresh task/review state plus the model using the existing admin debug full-model read (`debug=true&debug.fullModel=true`). It requires the returned `__debug_options__.fullModel === true` marker, then removes transport debug metadata. Ordinary model GETs apply display filters, notably `filterMissingRevisions`; their projection is not used as a whole-model save base. The named published-deletion filter is currently a stub, not a demonstrated deletion mechanism.

Correction targets are restricted to the selected revision's fields and dependency/canonical values. Entity ownership is checked before projecting fields: unrelated or revision-deleted entity subtrees are excluded even when their children are canonical. Every ancestor must belong to the selected revision, its dependency chain, or canonical data. The existing `filterRevises` helper hides superseded eligible instances without destructive ID normalization; unrelated draft entities cannot suppress an eligible canonical entity. Thus an empty canonical template superseded by a contribution is not offered as another contribution value; unsuperseded inherited values remain available. Selected revised selectors use their actual stored IDs, not the display resolver's synthetic copy. A selector rooted in another revision is excluded even if it carries a selected-revision child; selector ancestry/ownership changes are checked again at save.

A save applies explicit value/selector-state patches to a clone of the fresh full model. It rejects missing/new/other-contribution targets, duplicate IDs/patches, structural operations, changed model structure or revision metadata, changed target values/regions, changed target ownership/ancestry, and a selector that has acquired a different effective revision. Unchanged patches preserve the concurrent stored value. Untouched instances, canonical templates, other revisions/selectors, authors, IDs, approval and task state are retained. It never calls `mergeDocument`, which mutates and can canonicalize newly inserted instances.

After success `correction-cache.ts` marks model-preview, single-review, review-list and relevant resource/published model queries stale through the active `useQueryCache()`, with automatic refetch disabled. Mounted model/review refetch callbacks then refresh through their real loaders. The review provider is remounted by a session key after save/cancel. The context/actions wrapper is a stable top-level component, so ordinary parent updates do not recreate its subtree. Save/Cancel restore focus to the correction action. A successful write followed by refresh failure is reported as a refresh failure, rather than inviting a second save.

`correction-search.ts` refreshes each distinct canvas/manifest target after persistence through the existing `/api/madoc/iiif/canvases/:id/index` and `/api/madoc/iiif/manifests/:id/index` endpoints. It uses a local typed `ApiClient.request` call so HTTP failures, HTTP 200 warnings, failed imports and incomplete indexed totals remain observable. It does not force indexing: `noSearch` without warnings and the global disabled-search `typesense:null`/empty-warning response are intentional skips. Cleanup warnings on `noSearch` still fail. All affected targets are attempted. No legacy indexing or approval/task/review mutation is involved.

Persisted state locks value editing and Save before indexing begins. Search failure shows “Corrections saved, but search could not refresh” and offers a search-only retry; retry never performs another model PUT. Closing a saved form refreshes the review as saved work. Review/cache refresh failure remains distinguishable from a failed write.

## Persistence evidence and limits

`src/capture-model-server/routes/update-capture-model.ts` uses `userWithScope(['models.create'])`; full-model reads use `userCan`, which also honors `site.admin`. `routes/capture-model.ts` already exposes the authorized full-model debug read. No endpoint or global client change is needed.

Whole-model PUT still lacks server compare-and-swap: another write between the final read and PUT can race. The UI does not claim atomic conflict protection. Existing-value conflicts detected during the final read fail visibly and keep edits. Structural, revision-owned snapshot/alignment changes need separate persistence work and are excluded.

The repository revision upsert updates status/label/approval on existing rows but leaves `revision_data` unchanged. This implementation preserves revision metadata and never uses that route to change alignment or authors. Approval/task/notification/feed transitions are not used as a correction mechanism. Whole-model PUT has no approval-triggered search-index update, so this form explicitly requests targeted search refresh after persistence. Indexing is a separate operation and can fail after the write succeeds; the UI preserves that distinction.
