# Madoc Documentation

Use `services/madoc-ts/tools/documentation.mjs` rather than building separate browser automation. Read `services/madoc-ts/documentation/README.md` before adding a scenario.

## Workflow

1. Work from `services/madoc-ts` with Node 24 and pnpm 11.
2. Add a plain `.mjs` scenario under `documentation/scenarios/`. Reuse `createProject`, `createUser`, `importManifest`, `login`, and `waitForTask`; use session `page` or `api` only for scenario-specific work.
3. Keep `MADOC_CLIENT_ID` and `MADOC_CLIENT_SECRET` in the ignored `services/madoc-ts/.env`. Never print, copy, or commit them. The helper loads this file automatically and restricts bearer credentials to the configured Madoc origin.
4. Prefer stable locators and wait for the scenario-specific page state the screenshot demonstrates. Do not add arbitrary sleeps. Session navigation and screenshots already wait for Vite hydration; `session.screenshot()` also disables animations, hides the caret, and creates the output directory.
5. Run `pnpm docs:screenshot <scenario>`. Set `MADOC_SCREENSHOT_DIR=../../docs` when the requested artifact belongs in the repository's top-level `docs` directory.
6. Inspect the generated PNG and rerun after correcting scenario or layout problems.

Scenarios mutate the configured Madoc installation. Default to `https://madoc.local` and disposable documentation data unless the user explicitly authorizes another target. Make named users rerunnable through `createUser`; use unique project slugs when preserving old runs is useful.

Let `createUser` own account activation, interrupted-run recovery, and password reset. Madoc activation links are GET-only and their forms post to the sibling `/reset-password` route; admin reset links do not reactivate inactive users, and inactive accounts are absent from the search-only endpoint. The helper handles all three details.

Use `login` for role-specific sessions. It submits Madoc's normal login form through the browser context and opens pages with the resulting signed cookie, avoiding dev-server navigation races.

In local development, the Vite banner is CSS generated by `body.dev-loading:after`, not DOM text. The helper waits for Madoc's `#react-component.react-loaded` hydration marker, then for removal of `body.dev-loading` after navigation and before capture; do not duplicate this ordered wait in scenarios. Bearer-backed browser sessions also set Madoc's JWT cookie because client hydration only reads the cookie.
